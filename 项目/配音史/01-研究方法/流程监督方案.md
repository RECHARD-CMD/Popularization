# 流程监督方案

**版本：V1.2（学生 / 异地异步版）**
**日期：2026年11月25日**
**配套：**《创作流程》V1.2（`01-研究方法/创作流程.md`）
**适用范围：** 配音史子项目，两人协作，异地、时间不重叠、以学生课业为主。

**监督对象：** 流程有没有按顺序走、每一步有没有留下可查的证据、没过关的有没有处置。
**不监督：** 结论对不对、文案写得好不好、剪辑水平。

> **V1.1 → V1.2 改了什么：** 补来源登记表的最小结构与示例行，三条公式可以直接落地；时间预算由误写的 90 分钟统一为 85 分钟；G2 与 G3 改为分阶段各自计时，不再写成并入 G3 的 10 分钟；G4 指向模板 07。

> **V1.0 → V1.1 改了什么：** 检查点从 6 个全量降到「4 个必做 + 2 个轻量」；签字全部改为异步；新增 90 分钟/期的时间预算；机器检查换成在线表格三条公式，不需要写代码；外部抽检给了三级降级台阶；新增忙季降级运行与免阻塞规则。原版按"两人每天都在同一间屋子"设计，跑不动。

---

## 零、前提

| 约束 | 后果 |
|---|---|
| 两人异地、作息不同 | 不能依赖同步会议与当面签字 |
| 学生，课业优先 | 监督必须能压缩到碎片时间，且允许降级 |
| 没有稳定第三方 | 外部抽检要有替代方案，不能写成必选项 |
| 没有专职记录员 | 台账必须 1 行就能写完 |

**目标不是严密，是能一直跑下去。** 一套每期要花 4 小时、跑三期就放弃的监督，不如一套每期 85 分钟、能跑一年的。

---

## 一、五条原则

1. **异步默认。** 任何检查都不要求两人同时在线。需要同步的只有争议，不是核对。
2. **时间盒。** 单个检查点不超过 20 分钟。查不完就抽检，不延长。
3. **机器先筛，人后看。** 能算的先用表格算完，人只看没通过的。
4. **不阻塞。** 对方不回应不卡住自己；只有「文案锁定」和「发布」两个点不能跳。
5. **查物证。** 每项检查落在能打开的文件或字段上，"我看过了"不算。

---

## 二、检查点与时间预算

| 检查点 | 性质 | 时机 | 签字人 | 单次 |
|---|---|---|---|---|
| G0 立项三问 | 轻量 | 开采前 | 自记，无需签字 | 5 分钟 |
| G1 数据 | **必做** | 初筛前 | 李（陈采集，李不采集） | 20 分钟 |
| G2 论证与反证 | 轻量 | 写文案前 | 不单独签字（自记） | 10 分钟 |
| G3 文案锁定 | **必做** | 进剪辑前 | 陈（李是作者） | 20 分钟 |
| G4 发布 | **必做** | 发布前 | 李（陈是剪辑） | 20 分钟 |
| G5 复盘 | **必做** | 发布后 7 天内 | 互查 | 10 分钟 |

G2 在写文案前完成，G3 在文案定稿后、进剪辑前完成；两者不在同一时段，也不合并计时。

**单期合计约 85 分钟**，不含返工。若一期出两条视频，监督约占工时 10%，可以接受；超过 25% 就砍检查点，不要砍产出。

### G0 立项三问（5 分钟，自记）

三问各写一行：需要哪几条证据、什么证据会改判断、最可能被质疑的数字能不能证明。写不进 `02-选题/` 的立项表就不算做完。不设签字——这一步的价值在写，不在审。

### G1 数据（20 分钟）

- **先跑表格三条公式**（见第五节），3 分钟筛出问题行。
- 人只看两件事：随机抽 3 条数据打开链接，确认页面内容与摘录一致；查不到的有没有标"待核验"且没进分析。
- 不过就退回，注明改哪条。抽 3 条是上限，不是起点。

### G2 论证与反证（10 分钟，独立计时）

- 抽 3 条结论性判断，倒查它们依赖的数据。
- 看一眼反证记录：有没有检索、找到什么、怎么处理。空着或只写"未发现反证"就算没过。
- 这一步不单独设 Gate，在写文案前完成，不单独签字；与 G3 分处两个阶段，不合并计时。

### G3 文案锁定（20 分钟，不含 G2）

- 抽 5 句口播，逐句对照来源。
- 看强度词：是否只用四档，有没有"证实""必然""所有"这类超出的词。
- 看版本：有没有版本号和锁定日期。锁定之后再改，要重新走这一步。

### G4 发布（20 分钟）

- 五项审核表（模板 07：事实 / 来源 / 强度 / 版权 / 匹配）是否填全，每项有没有证据，而不是只打勾。
- 成片与锁定文案的差异清单是否存在。清单为空但成片改过词，等于没查。
- **这个点不能跳。** 忙季降级也保留它。

### G5 复盘（10 分钟）

各写三行：哪一步最费时间、哪一步返工最多、有什么可复用的东西。新点子进候选池，错误进勘误台账。

## 三、异步签字怎么落

选一种固定用，不要每次换：

| 方式 | 写法 | 适用 |
|---|---|---|
| A 提交信息 | commit message 写 `GATE-G1 李 通过 11-20` | 已用 git 的期 |
| B 在线表格 | 台账一行，签字列填"李 11-20" | 最常用，手机可写 |
| C 聊天记录 | 微信/QQ 一句话 + 截图存 `06-发布与反馈/监督记录/` | 临时、赶时间 |

规则：

- **签字不用同时在线。** 签的人看完文件自己写一行就算，不需要对方在场。
- **允许 48 小时内回签**，期间下游可以推进，但 **G3 与 G4 必须先签才能往下走**。
- 事后补签无效。补签只在"当时确实签了、忘了记"时使用，且要写补记日期。

## 四、免阻塞与超时

| 情况 | 处理 |
|---|---|
| 对方 48 小时未回应 | 自己推进，产物标"待复核"，台账记欠账 |
| 同一检查点连续 2 次超时 | 改成"产出方自签 + 48 小时内补签"；逾期记欠账 |
| G3 / G4 无人可签 | 暂停。这两个点不允许单方通过 |
| 欠账累积到 3 条 | 下一期降产出（改双周一条），先清账 |

设一个 **30 分钟的共同窗口**（如周日 21:00，跨时区则取重叠时段）。窗口只用来处理争议和排下一期，不用于逐条核对——逐条核对必须异步做完。

## 五、低成本自动化（不用写代码）

在来源登记表旁边开一块区域，三条公式，配一次用一年：

| 检查 | 公式（示例，列名按实际改） | 命中含义 |
|---|---|---|
| 编号重号 | `=COUNTIF($A:$A,$A2)>1` | 该 SRC 编号重复 |
| 必填缺失 | `=COUNTA($B2:$D2)<3` | 链接/日期/类型有空 |
| 引用闭合 | `=COUNTIF(正文!$A:$A,"*"&$A2&"*")=0` | 该来源在正文里没被用到 |

**表格最小结构。** 第 1 行为表头，数据从第 2 行开始。模板 02 仍是单条来源的详录，表格只做登记索引，两者用 SRC 编号对应；允许先在表格登记，再补模板 02。

| 列 | 字段 | 示例 |
|---|---|---|
| A | SRC 编号 | SRC-20261113-001 |
| B | 原始链接或档案号 | https://example.org/item/123 |
| C | 获取日期 | 2026-11-13 |
| D | 来源类型 | 报纸 |
| E | 快照文件 | `20261113_申报_配音.csv` |
| F | 核验状态 | 已核验 / 待核验 / 存疑 |

另建一张“正文”表：A 列每行一段文案或一句口播，段落中出现 SRC 编号即可，第三条公式按此判断引用是否闭合。

剩下两项靠眼看，各 1 分钟：**快照文件是否存在**、**强度词是否只用四档**。

腾讯文档、飞书表格、Excel 都支持这三条。跑完只处理标红的行——这就是"机器先筛，人后看"。

## 六、外部抽检的三级台阶

| 级别 | 做法 | 成本 | 效力 |
|---|---|---|---|
| L1 | 找一位不参与的同学/室友/家人，随机点 3 条来源链接，10 分钟 | 低 | 强 |
| L2 | 发布 7 天后按陌生人视角回看，记 3 条可疑点 | 零 | 弱（自己查自己） |
| L3 | 每 3 期至少做 1 次 L1 | 低 | 兜底 |

L2 只能补充，不能替代 L1。连续 3 期"全部通过"时强制做一次 L1——全都通过通常说明检查在走过场。

---

## 七、忙季降级运行

考试周、实习期，允许降级：

- 只保留 **G4 发布** 和表格三条公式，其余检查点记欠账。
- 降级期间**降低产出频率**（双周一条），而不是继续砍检查。
- 连续 2 期降级 → 正式改成双周节奏，别硬撑。

---

## 八、记录

台账六列，一行写完：

`日期 / 检查点 / 谁签 / 抽查几条 / 未过的项 / 处置`

- 只增不改，写错追加更正行。
- 载体：在线表格（首选）；有 git 时在同一次 commit 里附一行。
- 版本绑定只要求"能对上"：commit SHA 或文档版本号，写一个即可，不强制 git。

---

## 九、度量（只留两个）

| 指标 | 怎么算 | 告警 |
|---|---|---|
| 逃逸错误 | 发布后 7 天内被发现的事实错误数 | 任何一条都要在 G5 写原因 |
| 欠账 | 未补完的"待复核"与降级项 | ≥ 3 条即降产出、清账 |

退回率、工时占比可选记录，不作考核。

---

## 十、例外

- **紧急通道：** 每期 1 次，仅限"不影响结论、只影响发布时点"，48 小时内补检，台账标"紧急"。
- **平台规则变化：** 只补 G3、G4 的规则复核，其他照常。
- **素材临时替换：** 涉及数字或结论表述，按退回处理，不走例外。

## 附录 B：版本变更

### V1.1 → V1.2（2026-11-25）

| 变更 | 原因 |
|---|---|
| 补来源登记表最小结构与示例行 | 三条公式缺少列定义，无法直接建表 |
| 90 → 85 分钟 | 与检查点合计一致 |
| G2 与 G3 改为分阶段各自计时 | “并入 G3”与 G2 写文案前、G3 进剪辑前的时机冲突 |
| G4 指向模板 07 | 五项审核原先没有固定载体 |

### V1.0 → V1.1

| 变更 | 原因 |
|---|---|
| 检查点 6 → 4 必做 + 2 轻量 | 六个全量检查在课业压力下必然放弃 |
| 签字全部改为异步、允许 48 小时回签 | 异地作息不重叠，同步签字等于停摆 |
| 新增 90 分钟/期预算与单点 20 分钟上限 | 没有时间上限的监督会被无限拖延 |
| 机器检查改为表格三条公式 | 学生不写代码；公式 5 分钟配一次，每期 1 分钟跑完 |
| 外部抽检改三级台阶 | 原版把"找第三方"写成必选项，两人项目做不到 |
| 新增免阻塞与超时规则 | 原版"一方缺席记欠账"在异地是常态，不是例外 |
| 新增忙季降级运行 | 不允许降级的设计，会在忙季被整体放弃 |
| 台账去掉 commit 强制绑定 | 用 git 的是少数；先保证有记录，再谈可追溯 |
| 度量 4 个 → 2 个 | 指标越多越没人记 |
